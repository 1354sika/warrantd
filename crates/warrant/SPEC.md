## 0. 三条不可让步的公理

1. **AI 是"有权限但不可信"的实体。** 账本完整性必须锚定在 AI 控制范围之外。
2. **账本存声明，不存真值。** 记录"谁在何时凭何证据、经谁同意，承认了什么"。现实推翻时追加更正事件，历史保留。
3. **没有签署的行动可以被执行，但不能被当成事实。**

---

## 1. 定位

Warrant 是一个**认定系统**：不产生事实、不搬运事实、不解释事实，只裁定"什么算发生过"。

不进入实时控制回路；不做知识库（知识库是本层的下游、可重建派生视图）；不解释模型内部；不规定事件粒度；不规定界面；**不认识任何具体软件**。

## 2. 条目

### 2.1 信封

```json
{ "spec": "warrant/1", "id": "sha256:<64 hex>", "body": { }, "signatures": [ ] }
```

| 字段 | 必填 | 语义 |
|---|---|---|
| `spec` | 是 | 版本标识，形如 `warrant/<major>`，跨版本重放按此路由 |
| `id` | 是 | `"sha256:" + hex(sha256(域前缀 ‖ canonical(body)))` |
| `body` | 是 | 条目本体，参与哈希 |
| `signatures` | 是 | **集合**（0..N），见 §2.4 |

`id` 只覆盖 `body`。签名覆盖 `body` 的规范字节（经 §2.4 的载荷）。信封本身不入哈希。

### 2.2 三类条目

`body.kind` 决定条目类型：

| `kind` | 是什么 | 谁写 |
|---|---|---|
| `claim` | 一条声明：我做了 / 我打算做 / 世界该是什么样 | AI、人、服务 |
| `observation` | 一条观测：我独立看到世界实际是什么样 | 验证器 |
| `testimony` | 一条证言：某人陈述了什么（注意：不是“世界是什么样”） | **仅人类** |

**拆开的理由**：一条声明在动作发生时就必须入账（此时还没有观测），观测只在后来才产生，而且可能永远不产生（适配器崩溃）。把两者塞进同一条，就记不下"AI 动过手、结果还不知道"——而这正是静默失败与崩溃发生的区间。

授权（grant）不是第三种条目，它就是一条 `claim`，只是 `type` 为 `warrant://types/warrant.authority.grant@1`。

### 2.3 声明条目（`kind = "claim"`）

| 字段 | 必填 | 语义 | 缺了会怎样 |
|---|---|---|---|
| `kind` | 是 | `"claim"` | 无法区分 |
| `type` | 是 | `warrant://types/<域>.<对象>.<动作>@<版本>` | 无法互认 |
| `actor` | 是 | `{id, kind}`，`kind ∈ ai｜human｜verifier｜service` | 不知道是谁说的 |
| `subject` | 是 | `{id, kind}` | 不知道对什么做的 |
| `action` | 是 | `{verb, args}` | 不知道做了什么 |
| `expect` | 是 | **断言集**：世界该变成什么样。必须是 `action.args` 的确定投影 | 矛盾判定不可复算 |
| `authority` | 是 | `{granted_by, grant_id, kind}` | 擅自行动，无法追责 |
| `scope` | 是 | `{valid_within, valid_across}` | 无跨域概念 |
| `horizon` | 是 | `{issued_at, expires_at}`，RFC3339 UTC | 凭陈旧状态行动 |
| `parents` | 是 | 因果父 `id` 列表 | 无因果链 |
| `supersedes` | 否 | 被本条目更正的条目 `id` 列表（见 4.3） | 无法更正 |
| `nonce` | 是 | 幂等键 | 重试产生重复事实 |
| `reserved` | 否 | 扩展区，v1 必须为空对象或缺失 | 无升级路径 |
| `chain` | 是 | `{seq, prev}`，见 §2.5 | 无法证明历史未被删改 |

### 2.4 观测条目（`kind = "observation"`）

| 字段 | 必填 | 语义 |
|---|---|---|
| `kind` | 是 | `"observation"` |
| `type` | 是 | `warrant://types/warrant.observation@1` |
| `actor` | 是 | 验证器：`{id, kind}`，`kind = verifier` |
| `subject` | 是 | 被观测的那条声明：`{id: <claim id>, kind: "warrant.entry"}` |
| `observation` | 是 | `{method, result, observed_at, tier, channel, evidence[]}` |
| `reason` | 否 | 当观测无法完成时说明原因（**必填于 `result` 缺失时**） |
| `parents` | 是 | 至少含被观测声明的 `id` |
| `nonce` | 是 | 幂等键 |
| `chain` | 是 | `{seq, prev}` |

`observation.tier` ∈ `C0｜C1｜C2｜C3`，见 §5.1。`evidence[]` 放可离线复算的产物引用（路径或哈希）。

**观测条目是投影的基元，不再被观测。** 这条必须写死，否则会无限递归（观测的观测的观测……）。它的可信度只来自：验证器身份密钥 + 通道档位。

### 2.5 证言条目（`kind = "testimony"`）

一条证言记录的是**某人陈述了什么**，不是“世界是什么样”。

| 字段 | 必填 | 语义 |
|---|---|---|
| `kind` | 是 | `"testimony"` |
| `type` | 是 | `warrant://types/warrant.testimony@1` |
| `actor` | 是 | **仅人类**：`{id, kind}`，`kind = human` |
| `subject` | 是 | 证言所指向的条目：`{id: <entry id>, kind: "warrant.entry"}` |
| `testimony` | 是 | `{statement, language, method, observed_at, refers_to}` |
| `parents` | 是 | 至少含 `subject.id` |
| `nonce` | 是 | 幂等键 |
| `chain` | 是 | `{seq, prev}` |

**为什么人类的话不能写进 `observation`**：观测的可信度来自“能被换个进程重跑”；
人类目视**不可重放**，因此它不是观测。把它塞进观测，会让“观测”这一概念失去可判定性。

**为什么不需要 `freeze`**：证言记录的是“某人说过某话”这一**已经发生、不可否认的历史事件**，
其权威只来自签名者身份。P3 保证只有人类能签证言，故不存在“AI 伪造证言”的路径。

**`testimony.statement` 必须逐字**：不得翻译、不得摘要、不得润色。
**AI 不得代笔人类证言** —— 这是本条目的全部意义所在。若需记录 AI 的转述，
那应写成一条 `claim`，并由人类用证言或冻结来追认。

**证言不进 `facts()`**：`facts()` 的语义是“已冻结的声明”。
证言经 `testimonies()` 读取，且**不得被任何投影当作声明使用**。

### 2.6 签名

```json
{
  "signer": { "id": "user:alice", "kind": "human" },
  "role": "declare | freeze | reject | witness",
  "alg": "ed25519 | es256",
  "key_id": "ed25519:<hex pubkey>",
  "sig": "<base64url, no padding>",
  "signed_at": "2026-09-12T03:05:00Z",
  "over": "sha256:<entry id>",
  "reason": "（可选；role=reject 时必填）"
}
```

| role | 谁能签 | 含义 |
|---|---|---|
| `declare` | 条目作者 | "这条是我说的" |
| `freeze` | 人类 | "我确认，入账为事实" |
| `reject` | 人类 | "我否决"。**必须带 `reason`** |
| `witness` | 外部组织 | 跨域效力所需的外部见证（v1 不产生，槽位必须存在） |

**没有 `attest` 这个角色。** 独立验证的结构化形态就是"一条指向该声明的观测条目"，不需要在别人的条目上补签。

签名输入字节 = `"warrant/v1/sig\x00"` ‖ `canonical(payload)`，其中

```json
payload = { "entry": "<entry id>", "role": "...", "signer": "<signer id>", "signed_at": "..." }
```

**任何附加字段（如 `reason`）必须并入 `payload` 之后再签名。** 挂在签名对象上却不进 payload，等于没有认证。

**签名只覆盖自己的条目。** 验证器不为声明者的授权、时限、作用域担保——它签的是自己的观测条目。

**`alg` 与 `key_id` 的可扩展约定（v0.5）**：

| alg | 公钥 | 签名 | `key_id` |
|---|---|---|---|
| `ed25519` | 32 字节 | 64 字节 | `ed25519:` + hex(公钥) |
| `es256` | SEC1 **未压缩**点 65 字节 | **原始 `r‖s` 64 字节**（不是 DER；硬件令牌/CTAP2 口径） | `es256:` + hex(公钥) |

签名输入字节**不变**（仍为 `"warrant/v1/sig\x00" ‖ canonical(payload)`）。新增 alg 属**兼容性变更**：不得改动既有 alg 的语义。

**信任锚（v0.5 落地口径）**：人类公钥登记表必须存在**引擎不可写**处——否则 AI 只要把锚换成自己的公钥、
再用自己的私钥签 freeze 即可伪造（密钥从未被破解，硬件令牌也拦不住）。ZeroPage 用
`HKLM\SOFTWARE\ZeroPage`（普通用户只读；宿主读后经环境变量注入引擎）。论证见
`kb/信任锚不可替换性-对抗同机AI-2026-09-29.md`。

### 2.7 账本链

入账条目的 `body` 必须带 `chain`：`{"seq": <int>, "prev": "<前一条 id 或空串>"}`（创世条目 `prev` 为 `""`）。

**链位必须在被签名的 `body` 之内**，不得放在信封里。放信封等于没设防：删掉一条中间记录、把后一条指针接过去，签名依旧全部有效。

链接哈希 `link_hash = sha256("warrant/v1/link\x00" ‖ canonical(chain))`。

校验：`entry[n].chain.seq == n` 且 `entry[n].chain.prev == event_id(entry[n-1])`，首个不成立处即篡改点。

**签名增长**：冻结发生在观测产生之后，因此同一条目会以**追加同一 `id`** 的方式再次落账（`body` 逐字节不变，`id` 与链位不变，`signatures` 增多）。实现必须按 `id` 合并签名集合。条目 `body` 一经入账不可变。

## 3. 规范序列化

**可执行定义是 `tools/canon.py` + `vectors/*.json`，不是任何一个库的默认行为。**

| 规则 | 内容 |
|---|---|
| 编码 | UTF-8，无 BOM |
| 空白 | 字符串外零空白 |
| 键序 | 按 UTF-8 字节序升序 |
| 字符串 | 先 **NFC 归一化**；`"` `\` `\b` `\f` `\n` `\r` `\t` 用短转义；其余 C0 与 DEL 用 `\uXXXX`；`/` 不转义 |
| 数字 | **仅整数**，signed 64-bit 内。禁浮点、指数、前导零、`+`、`-0` |
| 重复键 | NFC 归一化后重复即拒绝（不是"后者胜"） |
| 顶层 | 条目 `body` 必须是对象 |

域分隔：`warrant/v1/id\x00`（事件 id）、`warrant/v1/sig\x00`（签名）、`warrant/v1/link\x00`（链位）。

选 JSON 而非 CBOR 是**可审计性优先**：十年后必须能有人用文本编辑器读懂账本。

## 4. 投影：状态是算出来的

**状态不是被写进条目的字段，而是条目集合的纯函数。** 同一条声明 + 不同观测 = 不同状态。

### 4.1 断言比对

`expect` 与 `observation.result` 都是**断言集**（标量键值）：

| 结果 | 条件 |
|---|---|
| `contradicted` | 存在键 k：k 在 `expect` 中、且在 `result` 中、且值不等 |
| `consistent` | `expect` 中每个键都在 `result` 中且值相等 |
| `unknown` | 其余（键缺失、`expect` 为空、观测未完成） |

### 4.2 状态优先级

升序判定，**先命中者胜**：

| 序 | 状态 | 条件 |
|---|---|---|
| 1 | `SUPERSEDED` | 存在后续条目将其 `id` 列入 `supersedes` |
| 2 | `REJECTED` | 有来自人类的 `reject` 签名 |
| 3 | `CONTRADICTED` | 存在指向它的观测条目且比对为 `contradicted` |
| 4 | `WARRANTED` | 存在 `consistent` 观测（tier ≥ C1） **且** 有人类 `freeze` 签名 |
| 5 | `UNAUTHORIZED` | `authority.grant_id` 未解析到一条 `WARRANTED` 的 grant 条目 |
| 6 | `CONSISTENT` | 存在 `consistent` 观测（tier ≥ C1），但尚无 `freeze` |
| 7 | `UNKNOWN` | 有观测但不足以认定：比对为 `unknown`，或比对一致但 `tier < C1` |
| 8 | `EXPIRED` | 未 `WARRANTED` 且已过 `horizon.expires_at` |
| 9 | `PROPOSED` | 仅有 `declare`，无任何观测条目 |

**`CONTRADICTED` 优先于 `WARRANTED`。** 一个已冻结的事实被后来的观测推翻，状态必须退回 `CONTRADICTED`——这正是公理 2（存声明不存真值）在状态机上的落点。冻结不是不可撤销，是"在当时的证据下被承认"。

**`SUPERSEDED` 优先于 `REJECTED`**：更正不是否决，历史保留。

**`grant` 条目豁免第 5 条**（否则无法自举）：一条 grant 的有效性只由人类的 `freeze` 签名决定。

### 4.3 更正原语

更正 = 追加一条 `claim`，其 `supersedes: [<被更正的 id>]`。原条目保留、状态改为 `SUPERSEDED`。**永不改写历史。**

## 5. 读取 API

这是本层唯一新增的东西：**账本位于 AI 的读取路径上**。缺了它，账本只是旁挂审计。

| 接口 | 返回 | 强制约束 |
|---|---|---|
| `facts(scope)` | **仅** `WARRANTED` 且未过期的条目 | 必须先完成投影再过滤 |
| `hypotheses(scope)` | 其余全部条目 | 每条**必须携带** `state` 与 `actor` |

**禁止提供"读一切"的合并接口。** 一旦合并，AI 会把假设当事实读，整个方案当场崩塌。

### 5.1 观测通道档位

| 档 | 定义 | 可否支撑冻结 |
|---|---|---|
| `C0` | 同一会话读回 | 否 |
| `C1` | 新会话 / 新进程重开读回 | 是 |
| `C2` | 离线产物（文件哈希、导出文本），第三方可离线复算 | 是 |
| `C3` | 跨机 / 跨人复核 | 是 |

**动作通道与观测通道必须不同。** 同一个会话里"我改完再读回来"，读到的是同一份可能撒谎的状态——只能算 `C0`。适配器必须如实回报实际档位，**低报允许，高报致命**。

**冻结门槛（硬）**：`WARRANTED` 至少需要一条 `C1` 及以上档位、且**已在 `capability` 申报**的 `channel` 所产出的观测。

**硬判据：冻结条目的静默错误率恒为 0。**

## 6. 预留槽：所有权必须在设计阶段解决

这五条在 MVP 中全部空转，成本为零；事后补的成本是全部。

| 槽 | 内容 | v1 状态 | 占住的稀缺资源 |
|---|---|---|---|
| **S1** | `signatures` 是**集合**，不是定长二元组 | 只出现 `declare` | 可加入外部见证签名 |
| **S2** | `type` 是可解析标识符（URI），命名空间形式固定 | 只需本地解析 | 全局类型注册表 |
| **S3** | `scope` 显式区分域内与跨域效力 | 只填 `org:local` | 跨域定序 / 见证 |
| **S4** | 规范含**可判定的一致性档** + 测试向量 | §7 已发布 | 一致性认证 |
| **S5** | `spec` 版本字段 + `reserved` 扩展区 | `reserved` 为空 | 规范的编辑权本身 |

**S3 必须写死的规则句（这一句创造稀缺资源）：**

> 一条声明，只有在带有签发组织之外的一方出具的证据时，才在签发组织之外具有效力。

规范**不得**写"见证者必须是某某"——那会被 fork，且不道德。让信任自然集中，像浏览器根存储一样。

**铁律：核心必须小到可以被一个人在一个下午内审计完毕。广度全部放在边缘。** 哪天核心需要认识某个具体软件的名字，设计就已经失败了。

## 7. 一致性档（v1）

| 编号 | 要求 | 判定 |
|---|---|---|
| C1 | 规范序列化 | 全部 positive case 的 `canonical_sha256` 相同 |
| C2 | 事件 id | 全部 positive case 的 `id` 相同 |
| C3 | 违规拒绝 | 全部 negative case 必须被拒绝 |
| C4 | 签名输入 | 全部 positive case 的 `sig_sha256` 相同 |
| C5 | 账本链 | 篡改任一条目后，链校验必须在首个不一致处报错 |
| C6 | 断言比对 | 三态判定与向量一致 |
| C7 | 状态优先级 | 九档优先级与向量一致，`CONTRADICTED` 不得被 `freeze` 覆盖 |
| C8 | 读取分离 | `facts()` 与 `hypotheses()` 互斥且完备；`C0` 观测不得导致 `WARRANTED` |
| C9 | 授权解析 | `grant_id` 不可解析时状态必须为 `UNAUTHORIZED` |
| C10 | P1 值级包含 | `expect` 的值未出现在 `action.args` 中时必须拒绝入账 |
| C11 | P2 授权范围 | `type` 不在 grant 授权范围时必须拒绝入账 |
| C12 | P3 角色绑定 | AI 签观测或签冻结必须被拒绝 |
| C13 | P6 冻结绑证 | 无 `based_on` 或所引观测不合格的冻结必须无效 |

|---|---|---|
| `ReplaceComponent` 返回成功、`LastErrorMessage` 为空，而 `RLCValue(R1)` 仍是 `1000` | `evidence/.../out0-com_probe.txt` | 沉默失败已证实 |
| 64 位宿主无法实例化该 COM（`0x80040154`） | 同上 N1 / N10 | 适配器必须是 32 位独立进程 |
| **存在可信成功路径**：`RLCValue("R1") = 2200` 后读回 2200 | 同上 N4 | 可做对照实验 |
| 上述失败**落盘后依然失败**（重开其 SaveAs 产物仍读回 1000） | 同上 N5 | 不是"内存陈旧" |
| 文件级"画电路"已验证：`.cir` 导入 → `.ms14`，13/13 成功 | `MULtIsM/out/` | `act` 的主通道候选 |
| `ReportNetlist` 产出连通性报告，不含元件数值 | 同上 N7 | 只能作拓扑通道 |

**对照实验（v0.2 的正式验收案例）**：

| | 声明 A | 声明 B |
|---|---|---|
| 动作 | `RLCValue("R1") = 2200` | `ReplaceComponent("R1", … "2.2k")` |
| 动作返回 | 无错误 | 无错误、`LastErrorMessage` 为空 |
| 独立观测（C1，新会话重开） | `2200` | `1000` |
| 投影状态 | `CONSISTENT` → 可冻结 → `WARRANTED` | `CONTRADICTED` → 不得冻结 |

账本能分辨这两件事，命题即成立。**它分辨不了的唯一情形，是观测通道不独立。**

### 已知限制（v1 明确承认）

| 限制 | 影响 | 计划 |
|---|---|---|
| 适配器没有身份密钥 | 无法证明"这条观测是谁给的"。MVP 靠"核心自己拉起的进程"兜住；`C3` 档挡不住 | v2 |
| 本机时钟不可信 | `horizon` 的"过期即失效"在有敌意的前提下不成立 | MVP 先标注时钟来源，不假装 |
| 无多用户 / 委托 / 角色链 | 团队场景不可用 | v2 |

## 10. 污染防护

先把话说清楚：**账本无法保证"里面没有错误声明"**——这正是公理 2。能保证的是三条：

| 保证 | 机制 |
|---|---|
| 幻觉**不能直接进入** `facts()` | 必经 `C1` 或更高档观测 **且** 人类 `freeze` |
| 错误**永不消失** | 只追加；更正留痕，历史保留 |
| 被推翻的事实**必须显式退回** | `CONTRADICTED` 优先于 `WARRANTED` |

在此之上，六条准入规则。违反任一条，条目**不得入账**：

| 编号 | 规则 | 挡的是什么 |
|---|---|---|
| **P1** | `expect` 的每个值必须来自 `action.args`（见 10.1） | AI 自定义"什么算符合预期"，让观测永远一致 |
| **P2** | `type` 必须落在 grant 授权范围内 | 冻结一条无意义但一定成立的声明 |
| **P3** | **角色-身份绑定**（见下表） | AI 自证、AI 自冻 |
| **P4** | 针对同一声明的观测**全部入账**，不得过滤或挑选 | 选择性披露 |
| **P5** | 观测通道必须已在 `capability` 申报；临时换通道 = 新版本 | 挑一个永远报一致的通道 |
| **P6** | `freeze` 的签名载荷必须列出所依据的观测条目 `id` | 盲签 |

### 10.1 P1 值级包含（可机械判定）

1. `expect` **不得为空对象**，否则比对恒为 `unknown`，永远无法冻结；
2. `expect` 中**不得出现数组**；
3. 对 `expect` 的每个叶子标量值 `v`，`action.args` 的叶子标量值集合中必须存在与之**类型与值严格相等**的项（递归收集）。

**这是下限防护，不是"意义性证明"。** 它挡住"我说要做 A、却预期 B"；挡不住"我写一组值相同但无关的期望"。后者由 `type` 授权范围（P2）与人工签署（P6）兜底——**这一点必须承认，不能假装已解决**。

### 10.2 P3 角色-身份绑定

| 角色 | 允许签的 `signer.kind` |
|---|---|
| `declare`（claim 条目） | `ai` / `human` / `service` |
| `declare`（observation 条目） | **仅 `verifier`** |
| `declare`（testimony 条目） | **仅 `human`** |
| `freeze` | **仅 `human`** |
| `reject` | **仅 `human`** |
| `witness` | 外部组织（v1 不产生） |

**AI 不能签观测，也不能签冻结。** 这条一旦松动，"独立验证"立刻变成自证。

### 10.3 P6 冻结必须绑定证据

`freeze` 的签名载荷为：

```json
{ "entry": "<claim id>", "role": "freeze", "signer": "…", "signed_at": "…",
  "based_on": ["<observation id>", "…"] }
```

`based_on` 必须非空，且每一条都必须真实存在、指向同一条声明、且达到 `C1` 档。**没有 `based_on` 的冻结无效。**

**`grant` 条目豁免 P6**（自举）：授权由人类直接承担，不存在「关于授权的观测」。

### 10.4 不可保证的四件事（必须承认）

| 项 | 为什么挡不住 | 缓解 |
|---|---|---|
| **人盲签** | 人疲劳后不看证据就签 | P6 让签字绑定证据；抽样复核；分级确认 |
| **验证器本身作恶，或由 AI 生成** | `C1` 只保证"换个进程看"，不保证它诚实 | `C2` 离线产物可第三方复算；验证器代码独立审计；关键场景走 `C3` |
| **时钟被操纵** | `signed_at` / `horizon` 由写入方填 | 已知限制；v2 引入外部时间源 |
| **AI 可能读到人类私钥** | 密钥以文件形式与 AI 同机共存，AI 进程有读权限，**因此技术上可伪造人类签名** | v1 承认：P3 只约束 `signer.kind` 字段，约束不了钥匙持有者。**2026-09-12 起已提供口令封存**（scrypt n=2^15 r=8 p=1 + AES-256-GCM；`verify` 通过后明文密钥覆写并删除，见 §10.5）。仍未覆盖：口令须在与 AI 同机的终端键入（运行时捕获）；当前密钥仍由 AI 装配期生成。完整隔离仍需硬件令牌 / 独立签名设备 |
| **规范自身可被修改** | SPEC.md 与账本同在一个工作区，AI 有写权限 | 版本控制可追溯；v2 应将规范哈希写入每条条目（v1 个人预留槽已就位） |

前三条是技术局限；**第四条是本方案最大的认知风险。**

它意味着：在 v1 的实现里，“人类签名”只是一个协议约定，**不是一个物理事实**。口令封存把门槛从"直接读文件"提高到"取得口令"，**没有改变这句话的性质**。

任何基于本方案的高风险决策，在私钥隔离完成前，都不应被当作“有人类背书”。
