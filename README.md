# warrantd

**AI 没告诉你的改动，你也看得见。**

它不拦你的 AI，也不替它做事。它只做一件事：**一直在看，把「看见的」和「AI 说的」记在同一本账上**——
然后回答三个问题：它说的对不对得上、哪些变了却没人承认、你不在的时候发生了什么。

> **A resident third-party observer.** It makes what an AI agent did *independently recomputable*
> — including the changes it never mentioned. Apache-2.0.

---

## 一句话 vs 一段话

| 场景 | 用这句 |
|---|---|
| 仓库简介 / 社交名片 | AI 没告诉你的改动，你也看得见。 |
| 对同事说 | 它是个常驻的监工：AI 说改好了，它能自己去核；AI 没说改了，它也能发现。 |
| 对法务/采购说 | 只追加、带签名、可离线复算的审计账本，覆盖本地文件与 MCP 工具调用。 |
| **不适合说** | "AI 治理平台""智能体安全网关" —— 它不是网关，它拦不住任何东西。 |

## 它解决什么问题

AI 智能体做事时，你面对两个病：

**黑盒** —— 它说「我把配置改好了」，你只能信。它说「任务完成」，你不知道它是不是只改了一行就收工。

**滞后** —— 你手上的信息是十分钟前的，而世界已经往前走了。它基于过期信息干活，你事后才发现。

这两个病有一个共同的根：**你和世界之间那条通道，只存在于 AI 的上下文里。**它不说，你不知道；它说错，你查不出。

**warrantd 把这条通道变成一份持续的、可复算的、不依赖 AI 配合的记录。**

---

## 它怎么做的

三条设计，每条都是为了堵住一种"看起来没问题、其实没看见"的失效：

### 1. 观测面是**封闭白名单**

它只允许自己用九种方式看世界（读文件哈希、读目录结构、读 git 状态、读连接表对端…），
**表外的一律做不到** —— 不是"不推荐"，是结构上做不到。

> 为什么：一个监督世界变化的进程，如果自己能跑任意命令，它就分不清「世界变了」和「我自己弄的」。

### 2. 账本是**只追加 + 可离线复算**

每条记录有 `id = sha256(规范化 body)` 和链位（`seq` / `prev`），并且签名。
任何人拿到 `entries.jsonl` 都能用同一套规则**自己算一遍**，不必信 warrantd 的话。

```bash
warrantd verify        # 链 + 签名自检
```

### 3. 三种切片，一条世界流

| 切片 | 回答 |
|---|---|
| **说 vs 看** | 它说的和实际对得上吗 |
| **没申报的变更** | 哪些文件变了，但**没有任何 agent 说过它改过** |
| **你不在的时候** | 从你上次看到现在，世界变了什么 |

第二条是最值钱的：**它不依赖 AI 承认任何事。** 变了就是变了，没人申报就是没人申报。

## 30 秒试用

```bash
# 1) 编（需要 Rust 工具链）
cargo build --release

# 2) 进到你的项目，写观测面：要盯哪些路径，一行一个
mkdir -p .warrant && echo "src" > .warrant/watch.list

# 3) 看一次
./target/release/warrantd once

# 4) 改一个文件，再看一次
echo "// x" >> src/main.rs && ./target/release/warrantd once

# 5) 看"有什么变了但没人申报"
./target/release/warrantd unreported
```

### 让它一直在看（不装服务、手动开）

```bash
warrantd open      # 前台跑，关窗口即停
warrantd ui        # 打开面板（黑色信封），浏览器窗口，只监听本机
```

### 让 AI 主动来问（MCP）

```jsonc
// Claude Code / Cursor 的 MCP 配置里加一段
{"mcpServers": {"warrantd": {
    "command": "/path/to/warrantd", "args": ["mcp", "--repo", "/path/to/your/project"]
}}}
```

四个 + 一个工具：`warrant_status` / `warrant_since` / `warrant_unreported` / `warrant_admit` / `warrant_check`。

### 让 AI 调外部工具时也留下痕迹（代理）

```bash
# 原来是：{"command": "python", "args": ["kit/lceda/mcp_server.py"]}
# 改成：
{"command": "warrantd", "args": ["proxy", "--name", "lceda", "--", "python", "kit/lceda/mcp_server.py"]}

# 不知道该怎么改？它只打印、不碰你的文件：
warrantd wrap --file ~/.claude.json
```

## 你现在有多可观测？

```bash
warrantd admit
```

| 级 | 含义 |
|---|---|
| **L0 盲** | 没有账本或没有观测面 ⇒ 「没发生」这句话没有意义 |
| **L1 事后** | 有账本有观测面，但只在被问时扫 |
| **L2 持续** | 有东西在持续看 |
| **L3 全经** | L2 + 外部工具调用也经过代理 |

每一级都会告诉你**离下一级差什么**。

## 诚实边界

读结论前必须知道（**这一节比上面所有内容都重要**）：

1. **它拦不住任何东西。** AI 不调用它、不挂 proxy，它什么也看不见。它是观测，不是网关。
2. **"看不见"分三类**，`warrantd status` 会分组告诉你：结构性做不到 / 我们还没做 / 你选的形态 ——
   每条"还没做"都带补法。**不把工程欠账混进能力边界。**
3. **最高等级 L3 也不等于全覆盖。** 只覆盖本地文件 + **配置里包过 proxy 的** MCP。
   shell 直接跑命令、没包 proxy 的 server，都在外面。
4. **目录指纹只到 C0。** 它证明"这个目录变了"，不证明"哪个文件变成了什么"。要定论得对具体文件算哈希。
5. **mtime 只能发现"被碰过"。** 改了又改回来能看见，但中间改了几次、每次是什么，看不见。
6. **网络只看到对端地址。** 不知道传了什么内容 —— 那是抓包，属结构性做不到。
7. **账本关着的时候看不到。** 信使没运行，世界照样在变；下次打开只能和上次快照比。
8. **Linux 上的账本锁未实现。** 多进程并发写在 Linux 不安全（Windows 用 `share_mode(0)` 独占）。
9. **只有自测，没有第三方可复现的成绩。** 我们没有 SWE-bench 那一类的公开数据集结果 ——
   所以「比别的工具准」这句话，现在**说不起**。

**以上九条，就是它此刻的真实边界。** 少说一条，它就变成了它要反对的那种东西。

## 两条纪律

1. **观测者自己也是被控对象。** 它的观测方式是一张封闭表，它自己的副作用必须申报，它改自己的配置也要留痕。
2. **不返回判决。** 它只说「有几条独立证据、什么档位」，不说「对不对」。判断留给调用者 —— 也省得再养一个更笨的裁判。
