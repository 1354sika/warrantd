> - **非空** ⇒ **推论 / 复算**（输入含上游证据）⇒ 按 §2.2 与 §4.1 R5，与上游**合并**（`d_eff` 只降不升）。

## 0 总则

### 0.1 要解决的现象

幻觉最强的形态不是「说假话」，是**用低维冒充高维**：

- 一条证据，记成三条独立证据
- 一条串行链，记成两条并行通道
- 同一个人写的两份文件，记成两次独立复核

这三种在本系统的实测里都发生过（见 §1.4）。

### 0.2 本协议的做法

把判据从「**数条数**」换成「**数维数**」。

| | 旧 | 新 |
|---|---|---|
| 输入 | n = 有几条依据 | M = [v₁ … vₙ] |
| 判据 | n ≥ 2 就放行 | d_eff = rank(M) ≥ k 才放行 |
| 漏掉的 | 三条同源冒充三条独立 | 同源 → 秩塌成 1 → 拦住 |

**n − d_eff 就是幻觉的栖息地。**

### 0.3 本协议不做什么

- 不保证结论正确
- 不改变模型权重、不改写历史记录
- 不对 AI 的「诚实」做任何假设

### 0.4 一句话

> 协议不保证结论正确；它保证**证据不够时，系统没有权力说出口**。

### 0.5 术语

| 术语 | 符号 | 含义 |
|---|---|---|
| 来源向量 | vᵢ | 第 i 条依据的「出身」坐标 |
| 来源矩阵 | M | [v₁ … vₙ]，列为来源向量 |
| 声称维数 | n | 系统声称的依据条数 |
| 有效维数 | d_eff | rank(M) |
| 冗余度 | r | n − d_eff |
| 横截性 | τ | 三个失效域中，极大互不包含族的最大大小 |
| 深度 | N | 依赖图的幂零指数 |
| 宽度 | D | 依赖图的最大入度 |

## 1 数学内核

### 1.1 一次判定所需的一切，是一个矩阵

设一次判定依赖 n 条依据。第 i 条的来源向量

```
vᵢ = (carrierᵢ, randomnessᵢ, pathwayᵢ)
```

来源矩阵

```
M = [v₁ v₂ … vₙ]
```

于是：

- n = 声称有几条
- d_eff = rank(M) = 实际有几维
- r = n − d_eff = 冒充出来的条数

**判据 H**：当且仅当 r > 0，该判定含幻觉成分。

### 1.2 为什么秩编不出来

秩是矩阵在任意可逆线性变换下的不变量。所以：

- 改措辞、换命名、拆文件、补一段描述 —— rank(M) 一动不动
- 想让 d_eff 变大，只有一条真路：**换一条真正不同出身的依据**

这是本协议唯一依赖的数学事实。

### 1.3 两侧同一个内核

| | 账本侧 | 激活侧 |
|---|---|---|
| M 的行 | 一条依据 | 一个样本 |
| M 的列 | 来源坐标（载体 / 随机性 / 通路） | 激活坐标（维度） |
| d_eff 低 | 同源冗余 | 危险子空间 |
| 算子 | 合并同源 | (I − BBᵀ) 投影 |
| 门的动作 | 不许冻结 | 不许输出 |

## 2 来源向量与合并规则

### 2.1 三个坐标

| 坐标 | 问什么 | 相同即同源 |
|---|---|---|
| **carrier** 载体 | 谁产出的字节？ | 同一进程 / 同一份代码 / 同一个文件 |
| **randomness** 随机性 | 是否共享同一份随机源或密钥？ | 同一把 ed25519 私钥 / 同一次采样 |
| **pathway** 通路 | 直接量到的，还是从别处推出来的？ | 复算的输入 = 上游的输出 |

**平行判据**：vᵢ ∥ vⱼ ⟺ 三项坐标全同。

**串联判据**：若依据 j 的输入即依据 i 的输出，则 vⱼ 含 vᵢ 的全部坐标 → vᵢ ∥ vⱼ → 合并为一根轴。

### 2.2 合并规则 —— 本协议的命门

**同一条账本，换一条合并规则，「过线数」差三倍。规则本身就是协议。**

以本快照实测（全部 180 条 claim）：

| 规则 | 合并键 | ≥2 轴的 claim | `mechanism.established` ≥2 轴 |
|---|---|---|---|
| **A** 域 + 证据指纹 | `(失效域, evidence 指纹)` | 76 / 180 | 40 / 106 |
| **B** 只按失效域 | `失效域` | 76 / 180 | 40 / 106 |
| **C** 只按证据指纹 | `evidence 指纹` | **23 / 180** | **0 / 106** |

**本协议采用规则 C，并再收紧一层（加串联判据）。** 人类裁决于 2026-09-17。

理由：规则 A/B 把「甲复算乙的输出」记成两根轴 —— 可那**是同一份字节**，不是两次独立观测。实测 53 对逐字节同序的观测里，最多的一对（40 条）正是这种结构。规则 A/B 会把它们全部放行，等于协议自动失效。

### 2.3 三条判据的优先级

```
串联判据（通路）  >  证据指纹  >  失效域
```

只要有一条命中「同源」，就合并，不管域是否不同。

### 2.4 本规则的已知盲区 —— 分轴只做**形式检查**（2026-09-17 增）

**必须写明，否则会被过度信任。**

判据只比较两件事：`evidence` 数组是否**逐字节相同**，或是否**互为子集**。
它**不检查**、也无法检查：某根轴的计算是否依赖另一根轴的输入。

| 它能防的 | 它防不住的 |
|---|---|
| 同一批证据冒充两根轴 | 把证据**分成两批文件**，而甲轴的计算其实吃的是乙轴的产物 |
| 引用了同一份字节 | 两份字节内容相关但哈希不同（如改个字段名再导出） |

**实测两侧**（2026-09-17，lceda 线协议 v1 重跑试点）：

- 合并侧：`claim-iceda-a9-entry-is-self-reported-0001` 的甲乙两轴引用**同一批 15 件证据**
  ⇒ 被判据正确合并为 1 根（`why=['同一份字节']`）；
- 分立侧：试点条两批文件互不包含 ⇒ 各自成轴（`why=[]`）。

**条文**：主张「真独立」的条目，**必须**在 `action.args` 里给出可复核的**独立性依据**，
至少包含：① 甲轴产物的可读源码位置；② 「它不引用对方产物」的可核验说明。
门槛**不强制**这一点 —— 它是**作者的自证义务**，由人类在 freeze 时审。

### 2.5 独立性代理 —— **预期先于接触**（2026-09-17 增）

> 凡主张「甲轴独立」的 claim，**必须**给出甲轴产物与对方产物的**时间顺序证据**
> （文件系统 mtime 或等价物），且顺序必须为「我方先」。

**实测**：试点条 `axisA/prediction.json` 落盘 `19:45:23`，乙轴最早产物 `19:47:26`，差 **122.5 秒**；
已钉进 `t_order.json`，并由离线复算器复核。

**★ 必须同时写明的限制**：

> **mtime 不是密码学证明** —— 有写权限者可任意改写时间戳。
> 它只能作为**辅助**证据，**不能**替代 §2.4 要求的源码可读性。

（本条纪律来自 Multisim 套件：那里要求 `predict.json` 的 mtime ≤ 成品 mtime。lceda 线此前没有这条。）

### 2.6 修轴次序 —— **优先修甲轴**，其次才采人证（2026-09-17 增）

> 当甲乙两轴因证据同源而被合并时，**优先**修甲轴（使其输入不取自目标软件产物）；
> **其次**才考虑采集丙轴（人证）。

**理由**（两条代价）：

1. **成本**：人证每次都要人到场。
2. **独立性**：人眼看的是**目标软件渲染出的同一界面** —— 丙轴与乙轴**失效模式相关**，
   并不独立于目标软件。丙轴的价值在「失效模式不同」，不在「数据源不同」。

**实测对照**（2026-09-17）：

| 路线 | 轴构成 | d_eff | 需要人类每次到场 |
|---|---|---|---|
| 老 41 条 | 轴1 = {乙,甲} 合并 ＋ 轴2 = 丙（人证） | 2 | **是** |
| 试点条 | 轴1 = 甲（自研 MNA 求解器，输入为我方 `design.json`）＋ 轴2 = 乙（软件自报） | 2 | **否** |

## 3 四条判据

### 3.1 J —— 证据重叠率（筛子，不是判据）

```
J(A, B) = |A ∩ B| / |A ∪ B|
```

A、B 为两条观测的 evidence 数组集合。J = 1 直接判为同一来源。
J 只用于快速筛查，**最终一律以 d_eff 为准**。

### 3.2 d_eff —— 有效维数（主判据）

```
d_eff = rank(M)
```

精确整数秩。坐标是离散的，**不做浮点近似**。

### 3.3 τ —— 横截性

三个失效域：甲（我方代码）/ 乙（对方软件）/ 丙（人的实测与目视）。
τ = 各域来源集合里，极大互不包含族的最大大小。

### 3.4 深度与宽度（两个量，不能合并）

- **深度 N**：依赖图的幂零指数，要求 A^N = 0（即无环）
- **宽度 D**：依赖图的最大入度，要求 D ≤ D_max

**幂零性只管深度，不管宽度。** 实测：深度 = 4，宽度 = 101。两者必须分开设限。

## 4 六个元协议

### 4.1 取数协议 —— 什么算「一条来源」

- **R1** 来源必须落成文件或字节，可被第三方重读
- **R2** 每条来源必须登记三项坐标
- **R3** 同一进程、同一时刻的两次读取，算一条
- **R4** 同一把密钥签出的两条「独立」验证，算一条
- **R5** 推论不得作为独立来源：若 B 的输入含 A 的输出，则 B ⊆ A

### 4.2 估计协议 —— 怎么算出 d_eff

- **E1** 由登记坐标构造 M
- **E2** rank 用精确算法（坐标离散，无浮点误差）
- **E3** 合并规则（§2.2）的版本号必须写进条目
- **E4** 快照必须带 sha256；**数字不绑快照即无效**

### 4.3 触发协议 —— 什么时候允许冻结

- **T1** d_eff ≥ k
- **T2** 对外交付类，至少 1 轴不是甲类
- **T3** 不得存在 CONTRADICTED
- **T4** 三条同时成立，人类签名才生效

### 4.4 强度协议 —— 差一点怎么办

- **S1** 同源合并只降轴数，不改写依据内容
- **S2** **不允许部分冻结**：要么够，要么不够
- **S3** 不允许用文字解释替代轴数

### 4.5 停止协议 —— 冻结之后

- **P1** 每次冻结后重算 d_eff
- **P2** 掉到 k 以下 → 状态回退，登记原因，保留历史
- **P3** 允许弃权：签 ABSTAIN，不判
- **P4** 弃权不消耗签名

### 4.6 扇出协议 —— 限宽（新增）

- **F1** 一条 grant 直接支撑的结论数 ≤ D_max
- **F2** 超过必须拆分授权
- **F3** 现状：101 条，超 D_max（=10）10 倍 → 已违规
